# Решение распространённых ошибок и проблем.
## 1. `Element not found: <selector>`
Ошибка, означающая, что элемент не был найден через `selector`. Скорее всего Вы допустили ошибку в написании, сверьтесь с руководством [режима Live Recording](Live_Recording_Mode_Guide.md). Действие останавливает выполнение всей сцены.

## 2. `ModuleNotFoundError: yaml` или другие зависимости
```bash
uv sync
```

## 3. OCR ничего не находит
проверьте:
1. установлен ли tesseract (`tesseract --version`),
2. контраст текста на скриншоте,
3. язык `ocr_lang` (`rus+eng`),
4. порог `ocr_min_conf` (начните с 0.25-0.35).

## 4. smart annotation не попадает в элемент
- уточните `target_text` (точная фраза с интерфейса),
- уменьшите `ocr_min_conf`,
- увеличьте `auto_padding`,
- попробуйте `target_index: 1` если на экране несколько похожих надписей.

## 5. субтитры выглядят плохо на светлом фоне
используйте:
- `subtitle_style: contrast` или `cinematic`,
- `subtitle_bg_opacity: 0.55..0.75`.

## 6. tts не работает / `SpeechConfigurationError: YANDEX_API_KEY не задан`
Для синтеза речи обязательно нужен валидный `YANDEX_API_KEY` в `.env` или переменных окружения. Без него любая сцена с `tts` поднимет исключение и остановит пайплайн. Если TTS не нужен — просто не указывайте поле `tts` в сценах.

## 7. `ffmpeg` не найден
установите ffmpeg через пакетный менеджер вашей os и проверьте:
```bash
ffmpeg -version
```

## 8. `gpu-screen-recorder не найден в PATH`
Wayland-сессии (Hyprland/GNOME/KDE) пишутся через `gpu-screen-recorder`. Установите его согласно инструкции на [git.dec05eba.com](https://git.dec05eba.com/gpu-screen-recorder/).

## 9. ошибка с путями к скринам
проверьте что `scene.path` ведёт к реальному png/jpg и путь указан относительно корня запуска.

## 10. `pydantic_core._pydantic_core.ValidationError`
Скорее всего вы указали какой-то аттрибут, но ввели невалидное значение в него. Например, написали `123` в поле `type` у какого-нибудь `action`, что не подходит. Ознакомьтесь с текстом ошибки, в консоли будет выведено что именно можно вводить, и что именно ввели вы.

## 11. `BrowserDriverError: Не удалось установить ChromeDriver` / `GeckoDriver`
Скорее всего нет интернета или заблокирован доступ к репозиторию драйвера. Проверьте сеть и повторите запуск. Драйверы скачиваются через `webdriver-manager` в `~/.cache/selenium/` (Chrome) и `~/.wdm/` (Firefox).

## 12. После live-сценария нет итогового `<title>.mp4`
Проверьте логи на ошибки. Если запись экрана состоялась, рендер произойдёт автоматически в блоке `finally`. Если рендер тоже упал — смотрите stacktrace в логах (`AA_LOG_LEVEL=DEBUG` для подробностей).

## 13. Live Recording: курсор виден в записи
По умолчанию курсор автоматически паркуется в правый нижний угол окна **один раз** при старте браузера. Если он всё равно виден в кадре — проверьте, что в сценарии нет действий `click` / `scrollTo`, которые двигают курсор к элементам. На Wayland (особенно с NVIDIA) флаг `cursor: false` в metadata не способен убрать курсор средствами рекордера, потому что software cursor plane захватывается всегда. Парковка через Selenium — единственный надёжный способ.

## 14. Live Recording: Selenium виснет на старте сессии
Симптом: запись экрана стартует, ChromeDriver/GeckoDriver запустился, но команда `POST /session` от Selenium не возвращается минутами. На Linux с двойным стеком IPv4/IPv6 (например Fedora) это может быть связано с тем, что `localhost` резолвится первым в `::1`, а драйвер виснет на IPv6. В проекте уже применяется патч `_force_ipv4_service_url` в `engines/live/browser_engine.py` — он заменяет `localhost` на `127.0.0.1` в URL драйвера. Если и это не помогает, проверьте версию Python: `requires-python = ">=3.13"` в `pyproject.toml`. На Python 3.14 selenium 4.x виснет из-за проблемы сериализации enum в JSON — используйте 3.13 (например через `pyenv install 3.13.12 && pyenv local 3.13.12`).

## 15. Live Recording: браузер открывается, но действия не выполняются
Проверьте `selector` действия — Selenium ищет элемент по XPath. Если элемент не найден или не виден на странице, поднимется `ActionExecutionError: Element not found: <selector>`. Возможные причины:
- неверный XPath (опечатка, лишний/недостающий слэш);
- элемент ещё не загрузился — увеличьте `wait` у действия;
- элемент находится внутри iframe (Selenium не пересекает их автоматически — нужно вручную через `driver.switch_to.frame`, текущий пайплайн этого не делает);
- элемент скрыт CSS (`display: none` / `visibility: hidden`) — внутренний `_find_displayed` его пропустит и поднимет ту же ошибку.

## 16. Live Recording: Firefox запускается медленно или зависает на kiosk
В некоторых окружениях `--kiosk` для Firefox требует, чтобы окно было активным. Закройте посторонние окна, поверх которых Firefox мог бы запуститься. При первом запуске GeckoDriver скачивается в `~/.wdm/` — это занимает время.

## 17. macOS: `UnsupportedPlatformError: ffmpeg не сообщил ни одного 'Capture screen'`
На macOS бэкенд записи — `avfoundation`, индекс screen-устройства определяется динамически через `ffmpeg -f avfoundation -list_devices true -i ""`. Если в выводе нет ни одного `Capture screen N` — это почти всегда означает, что у запускающего приложения (Terminal / iTerm / IDE) **нет разрешения Screen Recording**. Откройте `System Settings → Privacy & Security → Screen Recording`, добавьте туда ваш терминал/IDE, **полностью перезапустите** его и повторите запуск. Без этого разрешения ffmpeg молча пишет чёрный кадр.

## 18. macOS: курсор виден в записи несмотря на `cursor: false`
Для avfoundation проект передаёт ffmpeg флаг `capture_cursor=0` (а не `draw_mouse`, как для x11grab/gdigrab). Если курсор всё равно попадает в запись — проверьте, что у вас актуальная версия ffmpeg (`ffmpeg -version`, желательно ≥ 5.0). Дополнительно курсор паркуется в правый нижний угол окна браузера через Selenium — это страхует ситуацию, когда capture_cursor игнорируется конкретной сборкой ffmpeg.
