# Руководство по режиму Live Recording. 

**Про что это?**

Режим Live Recording позволяет автоматизировать простейшие действия в браузере, записать экран, а после обработать получившийся результат.
Благодаря этому режиму можно быстро и легко записать руководство прямо на платформе, ровно так, как это будет видеть пользователь.

**Плюсы использования режима:**
- Нет нужды в создании отдельных ассетов, таких как скриншоты и прочие элементы - всё уже вшито и работает из коробки.
- Точность. Под капотом используется `selenium` - лучший инструмент для автоматизации работы в браузере. Всё будет выполнено ровно так, как того требует описанный YAML-скрипт, без участия LLM или OCR.
- Практичность. Иногда показать какой-то функционал через скриншоты становится просто невозможно, в таком случае имеет смысл обратиться за помощью к режиму Live Recording.

**Минусы использования режима:**
- Зависимость от интернет-соединения. Для работы в браузере требуется интернет - без него режим работать просто не будет. Также от качества соединения зависит скорость открытия и перехода по вкладкам, что попадает в итоговое видео.
- Отсутствие умных аннотаций. В видео не получится вставить аннотации, которые будут подстраиваться под его элементы. Существует только возможность вставки заготовленных шаблонов в заготовленные места.

## Необходимые зависимости для работы режима
1. Стабильно-хорошее интернет-соединение.
2. `FFMPEG` — для Xorg/Windows.
3. `gpu-screen-recorder` — для Wayland.
4. Браузер. Поддерживаются `chrome` (по умолчанию) и `firefox`. Задаётся через `metadata.browser`.

## Особенности составления YAML-скрипта.
Основа YAML-скрипта предоставлена в [соответствующей документации](Script_Format_Specification.md)

Для Live Recording в сцене должны присутствовать действия (`actions`). Это именно то, что будет происходить в браузере: куда-то кликнуть, что-то ввести и т. д.

Каждое действие состоит из нескольких параметров:
- `type` - тип выполняемого действия в браузере, основной параметр, от которого зависят другие параметры. Доступные типы:
    - *navigate* - перейти по какому-то URL на какой-то сайт. Важно: переход будет от имени пользователя в текущей сессии, если предварительно должна пройти, допустим, авторизация, то при переходе на первоначальный адрес будет осуществлен редирект (перенаправление) на страницу авторизации.
    - *click* - нажать на какую-то кнопку. Подходит для любого элемента HTML (DOM). Если элемент не найден — пайплайн остановится с понятной ошибкой `Element not found`.
    - *wait* - бездействовать в течение какого-то времени. Часто нужно для демонстрации функционала, или подстраивания под TTS.
    - *input* - ввести определенное значение в форму. Важно: после ввода автоматически будет нажата клавиша ENTER, но её не всегда хватает для перехода по поисковику.
    - *scrollUp* / *scrollup* - поднять страницу вверх на определнное значение (регистр не важен).
    - *scrollDown* / *scrolldown* - опустить страницу вниз на определенное значение (регистр не важен).
    - *scrollTo* / *scrollto* - перейти к какому-то элементу на странице. Элемент будет отображен примерно в центре. Регистр не важен.
- **url** - обязателен для типа *navigate*. Указывает URL, куда необходимо перейти
  - **selector** - обязателен для типов: *click*, *input*, *scrollTo*. Указывает объект HTML, с которым будет проводиться действие. Шаблон (угловые скобки не писать): "//тег\[<параметр1> and <параметр2>...]". Параметров может быть сколько угодно, но как минимум должен быть один. Параметр строится по шаблону: "@аттрибут='значение'". Для поиска по тексту в тегах следующий формат: "text()='Текст'". Для поиска по началу значения: "starts-with(@attr, 'начало_значения_')". *selector* использует формат чистого xpath. Если слишком сложно, но пользоваться режимом хочется - есть решение. В браузере на странице нажмите клавишу F12: откроется меню разработчика и элементы HTML. Нажмите на любой элемент, с которым вы хотите взаимодействовать, а после правую кнопку мыши. Там найдите раздел COPY, а в нём будет что-то вроде *copy xpath*. Нажмите. Скопированное значение смело вставляйте в *selector*.
- **text** - обязателен для типа *input*. Указывает текст, вводимый в форму.
- **duration** - обязателен для типа *wait*. Указывает количество *секунд* бездействия. Неотрицательное целое значение (0 допустимо).
- **point** - обязателен для типов: *scrollUp*, *scrollDown*. Определяет количество единиц перемещения страницы. Это не количество пикселей, а абстрактное значение для браузера. Допустимо `0`.
- **behavior** - необязательный параметр для всех типов *scroll_*. Определяет поведение скролла, например `smooth` осуществляет плавный переход. Важно: работает только со статическими страницами, на страницы, которые подгружаются динамически через JS, behavior влиять не будет, вызывая ошибку, из-за чего скролл просто не сработает. Доступные значения:
    - *none (default)* - жёсткий переход без поведения
    - *smooth* - плавный скролл
- **wait** - длительность паузы **перед** выполнением действия (в секундах). По умолчанию `1`. Используется, чтобы дать странице/элементу время «доехать» до состояния, в котором действие будет успешным.
