# Руководство по режиму Live Recording.

**Про что это?**

Режим Live Recording позволяет автоматизировать простейшие действия в браузере, записать экран, а после обработать получившийся результат.
Благодаря этому режиму можно быстро и легко записать руководство прямо на платформе, ровно так, как это будет видеть пользователь.

**Плюсы использования режима:**
- Нет нужды в создании отдельных ассетов, таких как скриншоты и прочие элементы — всё уже вшито и работает из коробки.
- Точность. Под капотом используется `selenium` — лучший инструмент для автоматизации работы в браузере. Всё будет выполнено ровно так, как того требует описанный YAML-скрипт, без участия LLM или OCR.
- Практичность. Иногда показать какой-то функционал через скриншоты становится просто невозможно, в таком случае имеет смысл обратиться к режиму Live Recording.

**Минусы использования режима:**
- Зависимость от интернет-соединения. Для работы в браузере требуется интернет — без него режим работать просто не будет. Также от качества соединения зависит скорость открытия и перехода по вкладкам, что попадает в итоговое видео.
- Отсутствие умных аннотаций. В итоговое видео не получится вставить аннотации, которые подстраиваются под его элементы; работают только заготовленные шаблоны в заготовленные места.

## Необходимые зависимости для работы режима
1. Стабильно-хорошее интернет-соединение.
2. `FFMPEG` — для Xorg (Linux), Windows и macOS.
3. `gpu-screen-recorder` — для Wayland (Hyprland, GNOME, KDE Plasma и т. д.).
4. Браузер. Поддерживаются `chrome` (по умолчанию) и `firefox`. Задаётся через `metadata.browser` в YAML-скрипте. Соответствующий драйвер (`chromedriver` / `geckodriver`) скачивается автоматически через `webdriver-manager`.

## Как режим выполняется (под капотом)
Полезно понимать общий поток, чтобы корректно настраивать сцены:

1. **Запуск браузера и переход на стартовую страницу.** Браузер и драйвер инициализируются ДО старта записи. **Первое действие первой сцены обязано быть `navigate`** — оно выполняется тут же, чтобы загрузка стартовой страницы (и серый/белый kiosk-экран до неё) не попала в итоговый ролик. Если первое действие — не `navigate`, пайплайн поднимает `ValueError` и завершается: выполнять действия в браузере без открытой страницы невозможно.
2. **Парковка курсора.** Сразу после старта браузера курсор перемещается в правый нижний угол окна. Это сделано **всегда**, чтобы курсор не попадал в кадр на Wayland-сессиях, где штатные средства рекордера курсор скрыть не могут. Если вам **нужен** курсор в видео — добавьте действие `click` или `scrollTo` в нужной сцене: Selenium переместит курсор к элементу.
3. **Пре-генерация TTS.** Все аудиофайлы для сцен синтезируются заранее (один HTTP-запрос на сцену). Это нужно, чтобы блокирующие сетевые задержки Yandex SpeechKit не попадали внутрь записи — иначе на первом кадре висел бы kiosk-экран браузера, пока генерируется озвучка.
4. **Старт записи экрана.** Запускается процесс записи (FFMPEG или `gpu-screen-recorder` — выбирается автоматически по ОС/сессии). Параметры (`fps`, `cursor`) берутся из `metadata`. Запись начинается на **уже загруженной** стартовой странице. Перед первой сценой выдерживается короткая пауза (~0.3s), чтобы рекордер успел захватить первый кадр.
5. **Выполнение сцен.** Сцены идут по порядку (`scene_1`, `scene_2`, …). Внутри сцены — действия (`actions`) тоже по порядку. Первый `navigate` первой сцены уже выполнен до записи и в цикле пропускается. Если в сцене указан `tts`, длительность аудио учитывается: если действия выполнились быстрее, сцена будет добиваться `sleep` до конца озвучки.
5. **Остановка записи и рендер.** После последней сцены запись экрана корректно завершается, видеоряд монтируется через MoviePy, накладывается аудио (TTS, если есть) и итоговый mp4 сохраняется в выбранную директорию `-o` под именем `<metadata.title>.mp4`. Рендер выполняется в `finally`-блоке, поэтому даже при ошибке внутри сцены попытка собрать видео из уже отснятого материала будет произведена.

## Особенности составления YAML-скрипта
Основа YAML-скрипта предоставлена в [соответствующей документации](Script_Format_Specification.md).

Для Live Recording в сцене должны присутствовать действия (`actions`). Это именно то, что будет происходить в браузере: куда-то кликнуть, что-то ввести и т. д.

### Поля metadata, важные для Live Recording
- `mode: live` — режим (default).
- `browser: chrome | firefox` — выбор браузера.
- `cursor: true | false` — отображать ли курсор. Имейте в виду: курсор всё равно паркуется в углу при старте, но во время сцен с `click`/`scrollTo` он будет двигаться к элементам. На Wayland гарантировать **полное** отсутствие курсора в кадре можно только если не использовать действия, перемещающие курсор.
- `fps` — частота кадров записи (24 / 30 / 60).
- `language: ru | en` — язык TTS (если используется).
- `save_files: true | false` — сохранять ли промежуточные файлы (TTS-аудио, исходную запись) после рендера. По умолчанию `false` — всё лишнее удаляется.

### Параметры действия (`action_object`)
- `type` — тип выполняемого действия в браузере, основной параметр, от которого зависят другие. Регистр scroll-типов не важен (`scrollUp` = `scrollup`). Доступные типы:
    - **navigate** — перейти по URL. Важно: переход выполняется в текущей сессии браузера; если требуется авторизация и вы перейдёте на защищённый адрес, произойдёт редирект на страницу логина.
    - **click** — нажать на элемент. Подходит для любого элемента DOM. Если элемент не найден — пайплайн остановится с понятной ошибкой `Element not found: <selector>`.
    - **wait** — бездействовать в течение `duration` секунд. Часто нужно для демонстрации функционала или подстройки под TTS.
    - **input** — ввести текст в форму. Важно: после ввода автоматически нажимается ENTER, но не всегда этого достаточно для срабатывания формы.
    - **scrollUp** / **scrollup** — поднять страницу вверх на `point` единиц.
    - **scrollDown** / **scrolldown** — опустить страницу вниз на `point` единиц.
    - **scrollTo** / **scrollto** — прокрутить к элементу. Элемент будет отображён по центру.
- `url` — обязателен для `navigate`. Указывает URL.
- `selector` — обязателен для `click`, `input`, `scrollTo`. Чистый XPath. Шаблон: `//тег[@аттрибут='значение']`. Параметров может быть несколько через `and`. Для поиска по тексту: `text()='Текст'`. Для частичного совпадения: `starts-with(@attr, 'начало_')`. Если XPath кажется сложным — в DevTools браузера (F12) кликните правой кнопкой на нужный элемент → Copy → Copy XPath, и вставьте результат сюда.
- `text` — обязателен для `input`. Вводимый текст.
- `duration` — обязателен для `wait`. Целое число секунд, **0 допустимо** (в этом случае действие просто не делает паузу внутри себя).
- `point` — обязателен для `scrollUp` / `scrollDown`. Количество единиц перемещения (это не пиксели, а абстрактное значение для браузера). **0 допустимо**.
- `behavior` — необязательный для всех scroll-типов. Поведение скролла. Важно: `smooth` работает только на статических страницах; на страницах с тяжёлой динамикой плавный скролл может не сработать корректно. Доступные значения:
    - `none` (default) — мгновенный переход.
    - `smooth` — плавный скролл.
- `wait` — длительность паузы **перед** выполнением действия (в секундах). По умолчанию `1`. Используется, чтобы дать странице/элементу время дойти до состояния, в котором действие будет успешным.

## Поведение при ошибках
- **Элемент не найден** (`ActionExecutionError: Element not found: <selector>`) — пайплайн прерывает выполнение текущей сцены. Уже отснятый материал всё равно проходит через рендер (если успели накопить хотя бы одну сцену).
- **Драйвер не запустился** (`BrowserDriverError`) — нет интернета для скачивания драйвера, не установлен браузер или другая проблема инициализации. Выполнение завершается, рендер не запускается.
- **Запись экрана не запустилась** (`ScreenRecorderError`) — например, нет `gpu-screen-recorder` на Wayland или `ffmpeg` не в PATH. Аналогично прерывает запуск.

Все ошибки логируются с stacktrace при `AA_LOG_LEVEL=DEBUG`.
